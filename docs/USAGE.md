## 1. 安装

前往 [Releases](https://github.com/ZtestAi/z-switch/releases) 下载对应平台的安装包：

- **Windows**：`.exe`（NSIS 安装器）
- **macOS**：`.dmg`（区分 Apple Silicon 与 Intel，请按芯片选择）
- **Linux**：`.AppImage` 或 `.deb`

> 安装包未经 Apple 公证 / 未做 Windows 代码签名：Windows SmartScreen 可能提示「未知发布者」，macOS 首次打开可能提示「已损坏」或「无法验证开发者」。这属于正常现象，处理方法见 [FAQ](#14-常见问题-faq)。

## 2. 首次启动

首次运行时，z-switch 会自动完成三件事：

1. **保存原始配置** — 把本机现有的 Claude Code / Codex 配置完整快照到 `~/.z-switch/original/`，任何时候都能一键还原。
2. **建立官方账号卡片** — 为 Claude 和 Codex 各生成一张「官方账号」卡片，代表客户端本机登录状态。
3. **自动导入现有中转配置** — 若检测到你已经在用某个 API 中转站，会自动把它导入为一张供应商卡片并设为当前项。

## 3. 界面总览

- **顶部标签页**：在 **Claude Code**、**Codex** 与 **Grok** 三个分区之间切换，各自独立管理供应商。
- **右上角工具栏**：
  - **文档** — 打开本教程
  - **测速** — 一次性测试所有端点的 HTTP 往返延迟
  - **导入 / 导出** — JSON 形式备份或迁移供应商
  - **设置** — 主题、开机自启、本地路由代理等
  - **添加** — 新建一张供应商卡片
- **供应商列表**：每张卡片显示名称、地址、模型/协议标签，以及切换、真实测试、复制、编辑、删除等操作；卡片可拖拽排序。
- **批量管理**：列表上方「批量管理」可勾选多张卡片一次删除。官方账号卡片与当前正在使用的供应商不可勾选（后者请单独删除），批量删除不会改动电脑上当前生效的配置。

## 4. 添加供应商

点击右上角 **添加**，填写：

- **名称** — 便于识别的备注名
- **Base URL** — 中转站地址，支持智能推断（填入常见地址会自动补全）
- **API Key** — 你的密钥

### Claude 供应商

可分别配置：

- **主模型**
- **Haiku / Sonnet / Opus / Fable** 四个模型档位（分别对应不同用途，留空则用中转站默认）
- **1M 长上下文** — Claude 5.x 系列（Fable 5.1 / Opus 5.5 / Sonnet 5.5 / Haiku 5.5）原生支持 100 万 token 上下文，**无需勾选**。Sonnet / Opus / Fable 三档的「1M」开关只用于 4.6 等需要 `[1M]` 后缀才启用长上下文的模型（做法与 cc-switch 一致：给模型名追加 `[1M]` 标记，不额外写环境变量）。

### Codex 供应商

- 协议固定为 **`responses`**：Codex 已于 2026 年 2 月移除 `chat` 协议（`wire_api = "chat"` 会导致 Codex 所有命令启动失败），中转站需提供 `/v1/responses` 接口。
- 旧版本保存的 `chat` 供应商会在升级后**自动改为 `responses`**，`~/.codex/config.toml` 中残留的 `chat` 也会在启动时修正（修正前先备份）。
- 高级选项可设置推理强度 `model_reasoning_effort`（low / medium / high / xhigh / max / ultra），可用档位取决于模型。

### Grok 供应商

- 填写 Base URL（写入 `[endpoints].models_base_url`）、API Key 与模型，生成单文件 `~/.grok/config.toml`。
- Grok 没有本机官方账号卡片，分区初始为空。

保存前可先做 [连通性测试、模型拉取、测速](#6-供应商体检连通性--模型--测速--真实测试)。表单和 **JSON** 两种编辑方式可自由切换，适合高级用户直接粘贴配置。

## 5. 切换供应商

在目标卡片上点击 **切换**：

- **直连模式（默认）** 会立即把该供应商写入客户端配置文件。
- 切换**之前**，z-switch 会把当前生效（live）的配置**回填**到上一张卡片（backfill），避免你在配置文件里的手工修改丢失。

生效时机：

- **Claude Code** 通常在**下一次请求**时读取新配置，无需重启。
- **Codex CLI** 可能需要**重启**后生效。

## 6. 供应商体检：连通性 / 模型 / 测速 / 真实测试

每张卡片都提供以下能力：

- **连通性测试** — 检查地址与密钥是否可用。
- **模型列表拉取** — 从中转站拉取可用模型，便于选择档位。
- **测速（HTTP 层）** — 向端点发一次真实 HTTP 请求测往返延迟。**刻意不用纯 TCP**：本机若装了 TUN / 透明代理，TCP 握手会被就地应答造成「<1ms」失真，走 HTTP 层才能测到真实上游延迟。
- **真实测试** — 使用已保存的地址、密钥、模型和协议，向供应商发送一条最小的 `Hi` 请求（最多输出 32 tokens），在独立弹窗中实时显示**回复内容、首字耗时、总耗时**。
  - **模拟 CLI 请求**（弹窗左下角，Claude / Codex 可用）— 部分中转站的 Key 只放行官方客户端，普通测试会返回 403（如 `this key requires Claude Code CLI`）。勾选后按 Claude Code / Codex CLI 的请求头与请求体格式发送；该选项按卡片记住。做了更严格校验的中转站仍可能拒绝，此时以客户端实际使用为准。

> ⚠️ 真实测试会产生**极少量**模型调用费用。测试内容、模型回复与密钥**不写入任何持久化文件**，结果仅在本次运行中回显到卡片。

## 7. 官方账号卡片

「官方账号」卡片代表**客户端本机登录**，不保存任何 API Key：

- **Claude** — 切到官方账号时，会清除中转相关的环境变量，回到客户端自身的登录状态。
- **Codex** — 切走前会保存客户端刷新后的登录态，切回时自动恢复。

因此你可以随时在「API 中转站」与「官方账号」之间来回切换，互不干扰。

官方账号卡片右侧的**地球图标**可单独设置网络代理（跟随全局 / 自定义 / 不使用），适合只有访问官方服务时才需要代理的场景，详见 [网络代理](#网络代理claude-code--codex)。

## 8. 导入与导出

- **导出 JSON** — 把当前供应商列表备份成 JSON，用于迁移或存档。
- **导入 JSON** — 从 JSON 恢复供应商列表（覆盖）。默认只改 z-switch 的数据、不改客户端配置文件：
  - 本机各客户端**正在使用的供应商默认保持不变**（若导入文件里没有，会保留并继续作为当前项）；
  - 若导入文件里有**同一张卡片但地址 / 密钥不同**，导入前会弹窗让你逐个选择：
    - **保留本机版本** — 文件里的那张改用新 id 一并保留，不改动客户端配置文件；
    - **使用导入版本** — 以文件里的为准，并**立即写入该客户端的配置文件**（开启「写入前备份」时先备份；本地路由中只更新路由上游）；本机那张若不是空卡片，会改用新 id 一并保留，选错也能找回。
    - 本机那张缺少地址或密钥（可能已损坏）时，默认选「使用导入版本」，适合用之前导出的备份修复被清空的卡片；
  - 本地路由开关与端口、开机自启、Claude 联动开关、全局网络代理等与本机环境相关的设置保留本机值，其余设置以导入文件为准（供应商卡片上单独设置的代理随卡片导入）。

> 导入导出的是**供应商列表**，与首次启动保存的**原始配置快照**是两回事（后者用于「恢复原始配置」，见第 11 节）。

## 9. 本地路由代理（实验）

如果你希望在客户端**运行期间热切换**供应商、无需改配置或重启，可在 **设置** 中开启 **本地路由代理**。

开启后，z-switch 监听 `127.0.0.1:8899`（可在配置中覆盖），并把两个客户端的 Base URL 分别指向：

- `http://127.0.0.1:8899/claude`
- `http://127.0.0.1:8899/codex`

代理会根据当前选中的中转站注入鉴权信息并转发请求——**不修改请求体、不做协议转换、不记录用量**。切换中转站时会立即更新上游地址与鉴权。

**高级设置**（设置页）：连接 / 首段 / 流静默 / 非流式超时、请求体硬上限、连接池与 TCP Keepalive（流式返回与连接复用始终开启）。

**已知限制**：

- 代理**不会**同步改写已落入 live 配置的模型名。因此热切换只适用于**模型兼容**的供应商；跨模型切换仍需**关闭代理后直连切换**。
- 目前**不提供**自动重试或故障转移。
- 该模式仍在持续验证中，建议对稳定性有要求的场景优先使用直连模式。

失败请求会写入 `~/.z-switch/logs/proxy-errors.jsonl`，仅记录上游状态、脱敏 URL、失败阶段和截断后的错误详情，**不记录请求正文**；日志会自动脱敏密钥并按文件大小轮转，可在设置页打开目录或清空。

- **网络代理** — Claude Code / Codex 使用的全局默认 HTTP 代理（见下）
- **Claude 生态联动** — 让切换同步到 Claude 桌面版 / VS Code 扩展等（见下）

- **错误日志目录** — 一键打开或清空代理错误日志

- **关于** — 查看版本、检查更新；提供 GitHub 仓库与 Releases 下载页的「打开 / 复制链接」，自动更新不可用时可手动下载安装包

### 网络代理（Claude Code / Codex）

需要经本机代理（如 Clash、v2rayN 的 HTTP / 混合端口）访问官方账号或中转站时，可让 z-switch 自动为客户端配置代理，无需手动改环境变量：

- **全局默认** — 设置 → 常规 →「网络代理」填写地址（如 `http://127.0.0.1:7890`），留空表示不使用。可点「检测」确认端口能连通。
- **单独设置** — 在供应商编辑页（官方账号卡片点卡片上的地球图标）选择：
  - **跟随全局**（默认）；
  - **自定义** — 仅此供应商使用指定代理，**优先于全局默认**；
  - **不使用** — z-switch 不注入代理，沿用系统环境（不会清理你自己设置的代理变量）。
- 卡片名称旁的「代理」标签表示该供应商当前会走代理，悬停可查看地址与来源。

写入方式：

- **Claude Code** — 写入 `~/.claude/settings.json` 的 `env`（`HTTPS_PROXY` / `HTTP_PROXY` 及小写形式）。切换回填时会剔除这些由 z-switch 注入的变量，不会混进供应商数据。若供应商的 `env` 里已有你自己写的代理变量，以你的为准，z-switch 不再注入。
- **Codex** — 写入 `~/.codex/.env` 末尾由 z-switch 管理的区块（带注释标记，请勿手改）。文件里你自己写的其它行保持不变；不设置代理时不会创建、也不会改动该文件。
- **本地路由模式** — 客户端连接 `127.0.0.1` 不走代理，由本地路由按当前中转站经代理转发；官方账号仍按直连方式写入客户端配置。

注意：

- 仅支持 **HTTP(S) 代理**（Claude Code 不支持 SOCKS）；Clash 等工具的混合端口同时支持 HTTP，可直接填写。
- 修改代理后需**重启 Claude Code / Codex** 才会读取（本地路由下中转站之间的切换即时生效）。
- 连通性测试、拉取模型、测速和真实测试都会按该供应商的生效代理发送，与客户端实际线路一致。
- Grok 暂不支持网络代理。

### Claude 生态联动：桌面版 / VS Code 扩展 / 初次确认

z-switch 默认只切 Claude Code CLI（`~/.claude/settings.json`）。设置页的三个开关能把切换扩展到 Claude 的其它入口，均**跟随当前 Claude 供应商**、切到官方账号或恢复原始时自动撤回，且都只做**单字段增量读改写**（保留文件里其它内容，绝不整体覆盖；任一失败只记日志、不影响切换）：

- **Claude 桌面版随切换生效（仅 macOS / Windows）** — 让 Claude **独立桌面聊天 App** 也跟随切换。开启后：
  - 开着**本地路由代理**时，桌面版网关指向本地 `…/claude`，随你在 z-switch 里热切换供应商而跟随；
  - 关着代理时，桌面版直连当前供应商自己的地址；
  - 切回官方账号 / 恢复原始时，桌面版退回官方（1p）模式。
  - ⚠️ **改动后需完全退出并重开桌面 App 才会读取新配置**；未安装桌面 App 时该开关不产生任何写入。
- **应用到 Claude Code 插件（VS Code 扩展）** — VS Code 的 Claude Code 扩展有独立鉴权门槛，只改 `settings.json` 它不认。开启后写 `~/.claude/config.json` 的 `primaryApiKey`（切官方账号时清除），让扩展随第三方供应商生效。
- **跳过 Claude Code 初次安装确认** — 向 `~/.claude.json` 写 `hasCompletedOnboarding`，跳过 Claude Code 首次运行的引导 / 确认。

### 配置目录快捷入口

设置页「配置目录」提供四个按钮，在系统文件管理器中直接打开对应目录，方便手动查看 / 编辑：

- **Claude** → `~/.claude`（`settings.json`、`config.json`）
- **Codex** → `~/.codex`（`auth.json`、`config.toml`）
- **Grok** → `~/.grok`（`config.toml`）
- **z-switch** → `~/.z-switch`（`providers.json`、备份、日志）

> 目录不存在时会退回打开用户主目录（不会擅自创建 Claude / Codex / Grok 目录）。

## 11. 恢复原始配置 / 解除管理

- **恢复原始配置** — 把首次启动时保存在 `~/.z-switch/original/` 的快照写回客户端。恢复**之前**仍会保存一份时间戳备份，双保险。
- **删除正在使用的供应商** 时可选择：
  - 恢复首次原始配置，或
  - 保留电脑当前配置、仅解除 z-switch 的管理关系。

## 12. 深链导入（浏览器一键添加）

z-switch 注册了 `zswitch://import` 深链，网站 / 中转站可以生成这样的链接，用户点一下就能把供应商加进来，零负担接入。

安全上做了几道门槛：

- **点击后先弹确认框**预览要导入的内容（应用、名称、接入点、模型、**脱敏后的密钥**），用户确认才写入——不会静默导入。
- **绝不覆盖**已有供应商：同名会自动加数字后缀新增（`满血` → `满血 2`），弹框会提示。
- 接入点强制 `http(s)`；密钥不写入日志 / toast；支持用 `keyB64`（base64 编码，非加密）减少原文出现在 URL 里。

> 面向网站接入方：URL 参数规范见 [`docs/DEEPLINK.md`](./DEEPLINK.md)，并附一个可直接部署 / 参考的链接生成页 [`docs/deeplink.html`](./deeplink.html)。链接可能含 API Key，请仅在可信页面 / HTTPS 下分发。

## 13. 文件位置

| 路径 | 内容 |
| --- | --- |
| `~/.claude/settings.json` | Claude Code CLI 配置（直连模式写入 `env`） |
| `~/.claude/config.json` | VS Code Claude Code 扩展配置（`primaryApiKey`，开启插件联动时写入） |
| `~/.claude.json` | Claude Code 根配置（`hasCompletedOnboarding`，开启「跳过初次确认」时写入） |
| `%LOCALAPPDATA%\Claude`、`Claude-3p`（mac 为 `~/Library/Application Support/…`） | Claude 桌面版配置（开启「桌面版随切换」时写 3p 网关 profile） |
| `~/.codex/auth.json`、`~/.codex/config.toml` | Codex 客户端配置（直连模式写入） |
| `~/.codex/.env` | Codex 环境变量文件（设置网络代理时写入 z-switch 管理区块） |
| `~/.grok/config.toml` | Grok 客户端配置（直连模式写入） |
| `~/.z-switch/original/` | 首次运行保存的原始配置快照 |
| `~/.z-switch/backups/` | 每次写入前的时间戳备份 |
| `~/.z-switch/logs/proxy-errors.jsonl` | 本地代理的脱敏错误日志 |

## 14. 常见问题 FAQ

**Q：macOS 提示「“z-switch”已损坏，无法打开。你应该将它移到废纸篓」怎么办？**
A：应用并未损坏。安装包使用 ad-hoc 签名、未经 Apple 公证，从浏览器下载后会被系统加上隔离标记。把 z-switch 拖进「应用程序」后，打开「终端」执行：

```bash
xattr -dr com.apple.quarantine /Applications/z-switch.app
```

之后即可正常打开。若提示的是「无法验证开发者」，也可以先双击一次，再到「系统设置 → 隐私与安全性」底部点「仍要打开」（macOS 15 起右键 →「打开」已不再能绕过）。

**Q：Windows 提示「Windows 已保护你的电脑」怎么办？**
A：安装包未做代码签名。点「更多信息 → 仍要运行」即可。

**Q：Codex 报错 `wire_api = "chat"` 不再支持？**
A：Codex 已移除 `chat` 协议。升级到 z-switch v0.3.1 及以上后，启动时会自动把供应商和 `~/.codex/config.toml` 里的 `chat` 改为 `responses`（改前备份到 `~/.z-switch/backups/`）。如果中转站只提供 `/v1/chat/completions`、没有 `/v1/responses`，则无法再用于 Codex，请联系中转站或更换供应商。

**Q：切换后没生效？**
A：Claude Code 通常在下一次请求时生效；Codex CLI 需要重启。若仍无效，检查该卡片的 Base URL / 密钥是否正确，可用「连通性测试」验证。

**Q：我用第三方插件（如状态栏 ccline）改了 `~/.claude/settings.json`，切换供应商会覆盖它吗？**
A：**顶层字段（如 `statusLine`、`hooks`、`permissions` 等）始终保留**，z-switch 只替换 `env` 这一个顶层字段。但写在 `env` **内部**的第三方变量、以及 Codex `config.toml` 里的第三方段落（如 `[mcp_servers]`），目前是**按供应商卡片记忆**的：它们会跟随「切换离开时激活的那张卡片」，切到另一张卡片时可能暂时不在生效配置里（切回原卡片会恢复）。

**Q：真实测试会不会泄露我的密钥或对话？**
A：不会。测试内容、模型回复与 API Key 不写入任何持久化文件，只在本次运行内回显。

**Q：真实测试返回 403，提示 `this key requires Claude Code CLI` 之类？**
A：部分中转站的 Key 只放行官方客户端，Key 本身通常没问题。在真实测试弹窗左下角勾选「**模拟 CLI 请求**」后重试（Claude / Codex 可用，按卡片记住）。若仍被拒，说明中转站校验更严格，以 Claude Code / Codex 客户端里的实际使用为准。

**Q：「检查更新」失败 / 无法自动更新？**
A：自动更新需要访问 GitHub。网络受限时，到「设置 → 关于」点「手动下载新版本」的「打开」或「复制链接」，从 [Releases](https://github.com/ZtestAi/z-switch/releases/latest) 下载安装包直接覆盖安装即可，供应商与配置保存在 `~/.z-switch/`，不会丢失。

**Q：设置了网络代理，Claude Code / Codex 却没有走代理？**
A：① 修改代理后需**重启** Claude Code / Codex；② 只支持 HTTP(S) 代理，填 `socks5://` 会被拒绝，请改用代理软件的 HTTP 或混合端口（如 Clash 的 `7890`）；③ 切换后若提示「网络代理 … 无法连接」，说明代理软件未启动或端口不对，可在设置里点「检测」确认；④ 卡片若选了「不使用」，z-switch 不会注入代理。

**Q：本地路由代理和直连模式该用哪个？**
A：日常推荐**直连模式**（稳定、零中间层）。只有当你需要在客户端运行期间频繁热切换、且供应商之间模型/协议兼容时，再考虑开启**本地路由代理**。

**Q：开了「Claude 桌面版随切换」，切了供应商却没生效？**
A：桌面版**只在启动时**读取 3p 配置，请**完全退出并重开桌面 App**。另外该功能仅 macOS / Windows，且要你确实安装了 Claude 桌面聊天 App（未安装时开关不写任何文件）。若仍不生效，把 `%LOCALAPPDATA%\Claude-3p\claude_desktop_config.json` 与 `configLibrary\` 发到 Issues。

**Q：切换会不会动我 Claude 桌面版 / VS Code 扩展 / `~/.claude.json` 的其它设置？**
A：不会。这些联动都**只增量改写单个字段**（桌面版的 `deploymentMode` 与网关 profile、扩展的 `primaryApiKey`、根配置的 `hasCompletedOnboarding`），保留文件里其它内容；且默认全部**关闭**，需你在设置里手动开启。

**Q：为什么在这台电脑窗口是直角、别的电脑是圆角？**
A：无边框窗口的圆角由系统提供——**Windows 11 会自动圆角，Windows 10 没有这个特性**，因此同一个程序在 Win10 上是直角。这纯属外观，不影响功能。

**Q：配置文件坏了会被 z-switch 清空吗？**
A：不会。如果现有配置文件不是合法 JSON，z-switch 会**中止写入并报错**，绝不覆盖，以保护你的原有配置。
